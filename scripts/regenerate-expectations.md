# Regenerating the parity expectations

Two test suites compare against upstream rather than against expectations we
wrote ourselves. Both are generated, and both need regenerating whenever
upstream changes the behaviour they cover.

## Prerequisites

```bash
git clone --depth 1 https://github.com/dflook/terraform-github-actions.git /tmp/dflook-upstream

# Must be 7.3.1 — the version upstream pins in image/requirements.txt.
# 8.x returns values with their surrounding quote characters and block labels
# as `"s3"` rather than `s3`, which silently changes every expectation.
pip3 install 'python-hcl2==7.3.1'
```

## `__tests__/upstream-constraint-matrix.json`

Version constraint evaluation, generated by running upstream's own
`terraform/versions.py`.

```bash
cd /tmp
mkdir -p stub && cat > stub/requests.py <<'EOF'
class Session:
    def get(self, *a, **k): raise NotImplementedError
EOF
cp /tmp/dflook-upstream/image/src/terraform/versions.py .

python3 - <<'EOF'
import sys, json, itertools
sys.path.insert(0, 'stub')
from versions import Version, Constraint

ops = ['', '=', '!=', '>', '>=', '<', '<=', '~>']
bounds = ['1', '1.5', '1.5.0', '1.5.2', '0.13', '2.0.0']
versions = ['1.5.0','1.5.2','1.5.9','1.6.0','2.0.0','0.12.31','1.6.0-rc1','1.5.0-beta','0.13.5']

rows = []
for op, bound, ver in itertools.product(ops, bounds, versions):
    expr = f'{op}{bound}'
    try:
        allowed = Constraint(expr).is_allowed(Version(ver))
    except Exception as e:
        allowed = f'error:{type(e).__name__}'
    rows.append({'constraint': expr, 'version': ver, 'allowed': allowed})
json.dump(rows, open('constraint-matrix.json','w'))
print(f'{len(rows)} cases')
EOF
```

Copy the result over `__tests__/upstream-constraint-matrix.json`.

`versions.py` imports `requests` at module scope purely for the release index,
which these cases never touch — hence the stub.

## `__tests__/fixtures/`

Module reading, generated by running `python-hcl2` over the Terraform fixtures
in upstream's test suite. The fixtures themselves are copied into
`__tests__/fixtures/modules/` so the suite needs neither the clone nor Python to
run.

The generator lives in `scripts/generate-module-expectations.py`.

```bash
python3 scripts/generate-module-expectations.py
```

## If a regenerated expectation disagrees with us

Work out which side changed before touching our implementation. A new
expectation that contradicts a passing test usually means either upstream
changed behaviour — in which case we follow — or the generator ran against the
wrong dependency version, as happened with `python-hcl2` 8.x.
