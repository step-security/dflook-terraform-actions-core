# Masking fixtures

Each `*.txt` is a sample of Terraform output. The matching `*.expected.txt` is
what upstream produces for it.

The expectations were **not** written by hand. They were generated by running
the [`tfmask`](https://github.com/cloudposse/tfmask) tool that upstream's image
installs and pipes plan output through, under the environment that image sets:

```bash
git clone --branch 0.7.0 https://github.com/cloudposse/tfmask.git
cd tfmask && go build -o tfmask-ref .

export TFMASK_RESOURCES_REGEX="(?i)^(random_id|kubernetes_secret|acme_certificate).*$"

./tfmask-ref < plan-0.12.txt > plan-0.12.expected.txt
TFENV=0.11 ./tfmask-ref < plan-0.11.txt > plan-0.11.expected.txt   # older dialect
```

That distinction matters: hand-written expectations would only confirm our own
reading of the rules, and the rules have several counter-intuitive edges — see
`reproduces upstream leaving a bare password unmasked` in `mask.spec.ts` for the
sharpest one. Generating them from the tool is what makes these tests evidence
of parity rather than of self-consistency.

`TFMASK_RESOURCES_REGEX` is set because upstream overrides the tool's own
default with a wider list. Fixtures generated without it will differ.

To add a case, write a new `.txt`, regenerate its `.expected.txt` with the
commands above, and review the diff before committing.
